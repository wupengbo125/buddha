# 发愿与发愿集

Status: ready-for-agent

## Problem Statement

现有木鱼程序支持自定义佛号、敲击音效、当日次数和累计次数，但缺少可自行编排、逐步完成和分享的修心内容。用户希望像组合音乐歌单一样组合发愿，同时保持敲击首页简洁，不把现实生活的行为打卡变成过关条件。

目前只有本人使用固定账号，因此本次需要完整的内容创作、顺序发愿、公开审核和分享流程，而不是立即开放用户注册。

## Solution

- **发愿**：可独立创建、复制和分享的内容，包含名称、念诵内容、敲击提示和目标次数。念诵内容可以是佛号、咒语等，不限定为佛号。
- **发愿集**：按顺序编排的多个发愿，相当于歌单；参与者从头到尾依次完成。
- **收录**：保存独立副本并保留来源；副本可以自行修改，不跟随原作者修改，不继承他人的进度。
- **发愿进度**：只表示程序内有效敲击达到目标的情况，不记录现实行为，也不判断认知或修心效果。
- **公开内容**：通过审核后才可进入广场和通过分享入口访问的发愿或发愿集。

保留自由敲击。在独立的内容管理页面选择发愿集或返回自由敲击，首页只承担念诵、敲击和必要的进度展示。广场提供发愿与发愿集的发现、收录、收藏、点赞及排行榜。

## User Stories

1. 作为使用者，我希望保留自由敲击，以便不参加发愿集时仍能照常使用木鱼。
2. 作为使用者，我希望保留当日次数、累计次数和音效，以便既有使用体验不受影响。
3. 作为使用者，我希望首页不放自由模式与发愿模式切换按钮，以便专注敲击。
4. 作为创作者，我希望创建和编辑发愿的名称，以便表达自己的修心主题。
5. 作为创作者，我希望设置念诵内容，以便使用佛号、咒语或其他念诵文字。
6. 作为创作者，我希望设置敲击时浮现的文字或符号，以便用提示引导修心。
7. 作为创作者，我希望设置多条敲击提示，以便发愿时依次展示不同内容。
8. 作为创作者，我希望设置目标敲击次数，以便明确每项发愿的完成条件。
9. 作为创作者，我希望发愿默认私有，以便整理内容时不会提前公开。
10. 作为创作者，我希望在独立的“我的发愿”页面管理内容，以便不把内容管理塞入设置页。
11. 作为创作者，我希望创建并命名发愿集，以便组合自己认可的一套发愿内容。
12. 作为创作者，我希望把自己的发愿加入发愿集并调整顺序，以便编排发愿过程。
13. 作为创作者，我希望在多个发愿集中使用相同内容，以便复用内容而无需手工重写。
14. 作为创作者，我希望从发愿集中移除某一项，以便调整编排而不删除独立保存的发愿。
15. 作为参与者，我希望从发愿集详情开始发愿，以便回到首页直接敲击。
16. 作为参与者，我希望达到当前目标后自动进入下一项，以便按照发愿集顺序完成。
17. 作为参与者，我希望首页轻量显示当前发愿和进度，以便知道自己进行到了哪里。
18. 作为参与者，我希望敲击提示不要求手动关闭，以便连续敲击不被弹窗打断。
19. 作为参与者，我希望中途离开后能继续已保存的进度，以便分多次、跨多天完成。
20. 作为参与者，我希望切换发愿集时保留各自进度，以便之后回来继续。
21. 作为参与者，我希望在管理页面返回自由敲击，以便首页继续保持简洁。
22. 作为参与者，我希望完成全部发愿后看到完成状态，并能主动重新开始，以便决定是否再修一遍。
23. 作为参与者，我希望发愿敲击同时计入当日与累计次数，以便同一次敲击不被遗漏或重复计算。
24. 作为参与者，我希望“清淡饮食”等提示只作为修心内容，以便无需填写现实行为打卡。
25. 作为浏览者，我希望分别浏览公开发愿和发愿集，以便找到单项内容或完整组合。
26. 作为浏览者，我希望搜索名称和简介，以便快速找到感兴趣的内容。
27. 作为浏览者，我希望看到内容详情、作者、目标次数及发愿集顺序，以便开始前判断是否适合自己。
28. 作为使用者，我希望复制公开发愿到自己的内容库或发愿集，以便自由组合别人的公开内容。
29. 作为使用者，我希望复制整份公开发愿集，以便不逐项重建完整编排。
30. 作为使用者，我希望修改副本的念诵内容、提示和目标次数，以便调整为适合自己的发愿。
31. 作为使用者，我希望副本保留来源且不随原作者修改，以便既尊重创作者又维持自己的内容稳定。
32. 作为使用者，我希望收藏公开内容，以便稍后找到，而不必立即生成副本。
33. 作为使用者，我希望点赞或取消点赞，以便表达对公开内容的认可。
34. 作为浏览者，我希望按点赞排行或最新发布浏览，以便发现受欢迎的内容和新内容。
35. 作为创作者，我希望分享审核通过的内容链接，以便其他可访问本站的人查看内容。
36. 作为创作者，我希望所有公开内容先经过审核，以便不绕过平台发布规则。
37. 作为创作者，我希望公开内容修改后重新审核，以便修改后的文字也经过同样的发布流程。
38. 作为创作者，我希望私有内容不能通过广场或分享链接泄露，以便控制公开范围。
39. 作为创作者，我希望取消公开后停止新的访问和收录，以便撤回公开入口，但不删除别人已有的独立副本。
40. 作为当前唯一使用者，我希望继续使用现有账号，以便无需先建设注册和密码找回系统。
41. 作为维护者，我希望内容、进度、收藏和点赞都具有明确的数据归属，以便以后开放多用户时能隔离用户数据。
42. 作为维护者，我希望审核通过独立接口调用，以便目前默认通过、以后接入实际 AI 审核服务。

## Implementation Decisions

### 保留与扩展

- 沿用现有 Next.js 页面、API、D1 数据存储及木鱼交互，不重建独立应用。
- 保留既有自由敲击数据、图片、字幕和音效设置。新发愿使用“念诵内容”字段，不把旧佛号数据自动迁移成公开发愿。
- 新增内容管理、发愿集编排、发愿进度、公开发现及审核模块；扩展现有计数链路以支持发愿中的敲击。
- 使用新增数据库迁移，保留已应用迁移；本地数据库与部署环境采用同一套迁移。

### 内容与复制

- 发愿保存所有者、名称、可选简介、念诵内容、有序提示列表、正整数目标次数、公开状态、来源和时间信息。发愿集保存所有者、名称、可选简介及有序条目。
- 每个条目代表发愿在该发愿集中的一次出现。即使内容相同，也逐项完成，不共享或抵扣其他条目的进度。
- 收录公开发愿生成归属于当前用户的私有副本。收录公开发愿集同时复制其有序内容，保留来源，不继承点赞、收藏、公开资格或发愿进度。
- 副本可以独立修改。原作修改、取消公开或删除不影响已有副本；来源失效时仍保留原作者与原名称的归属记录。
- 删除发愿集只移除该集和对应的个人发愿记录，不删除独立内容库中的发愿。删除仍被自己发愿集引用的发愿前，应提示先从相关发愿集中移除。
- 已开始的一轮发愿保存当时的内容和顺序；之后编辑原内容不改变这一轮的目标与进度。重新开始时使用当前内容。无需引入通用内容版本管理界面。

### 顺序推进与计数

- 一轮发愿从第一项开始，达到目标自动进入下一项；当前项完成前不可跳关。一次敲击只归属当时的一项，不因切换而重复计入下一项。
- 同一时间只有一个当前发愿集；切换或退出只暂停，不清零。完成全部内容后进入完成状态，下一次敲击不隐式重开；用户可以主动重开或切回自由敲击。
- 进度按用户、发愿集当前轮次和条目保存。跨日仅重置当日统计，不重置发愿目标进度。无需连续天数、现实行为确认或认知评估。
- 保留现有自由敲击的逐项计数。发愿敲击同时更新对应发愿的个人计数与当前条目进度；当日和累计汇总按有效敲击计算，不能把同一次事件从多个统计来源再次相加。
- 沿用客户端事件标识去重机制；发愿事件同时携带本轮和条目归属。服务端验证目标归属与当前顺序，不能由客户端任意提交下一项进度。
- 去重记录、计数及进度推进必须作为一次原子操作处理；重试、重复请求或并发点击不能导致漏记、重复过关或部分成功。重复请求返回已提交的结果。
- 服务端返回权威计数、当前条目和完成状态，客户端协调乐观展示。迟到响应不能把界面退回旧进度；切换后的旧请求不能记到新发愿集。
- 延续现有时区设置。当日统计按事件原日期归属；旧日期重试不能覆盖当前日期的当日统计。
- 当前重试队列仅在内存中，保持这一使用边界。已成功保存的进度可在刷新后恢复；失败时明确显示未同步，不声称关闭页面后还能恢复未发送点击。

### 页面与交互

- 敲击首页保留木鱼、念诵内容、当日及累计次数；发愿时只增加当前标题、进度和轻量提示。模式选择放在首页之外。
- “我的发愿”管理单项内容；“我的发愿集”管理组合、顺序和个人进度。它们是独立业务页面，不藏在设置中。
- 发愿编辑支持念诵内容、目标次数和有序提示；发愿集编辑支持选择、移除及排序。排序必须同时支持触屏操作，不依赖桌面拖拽。
- 多条提示按敲击顺序轮换，文字或符号轻量浮现，不要求逐次关闭弹窗。完成过关采用短暂反馈，不阻断连续敲击。
- 广场分“发愿”和“发愿集”，提供搜索、最新发布和点赞排行；同赞数使用稳定的时间及标识排序，不做个人发愿成绩排行。
- 详情页区分“收藏”“复制到我的内容”和“开始发愿”。开始他人公开发愿集时，先形成自己的独立副本，再记录个人进度。
- 收藏仅保存引用，不复制内容或进度；原作撤回时显示不可访问，不泄露原文。每个用户对每份公开内容最多一份收藏、一份点赞，支持取消且重复操作幂等。
- 所有页面遵循现有视觉风格，适配桌面和手机，处理加载、空列表、错误、保存中及不可访问状态。

### 公开与审核

- 私有、待审核、已公开和审核未通过是不同状态。只有审核通过的公开内容进入广场、搜索、排行及分享读取入口。
- 审核接口接受内容类型、标识及本次提交的内容快照，返回通过或拒绝及可选原因。当前适配器默认通过，但发布路径必须实际经过接口，不能直接跳过审核。
- 将来接入 AI 服务只替换适配器。接口错误时保持未公开并允许重试，不以默认通过作为故障兜底。
- 审核结果只适用于送审的具体内容；审核期间再次修改后，旧结果不能公开新文字。真实异步任务平台不在本次范围，但接口与发布状态必须保留这个约束。
- 已公开内容的修改形成待审核稿，审核通过前仍展示旧的通过版本；审核拒绝或失败不把新稿暴露到公开接口。
- 发愿集的名称、简介、顺序及收录内容都必须属于通过审核的公开版本。发愿集含有私有或未通过审核的发愿时，不允许直接公开；提示作者先处理相关发愿，不能隐式公开私人内容。
- 收录的副本即使来自已审核原作，也作为新内容在再次公开时审核。私有副本的自由修改不触发公开发布。
- 取消公开或删除后，新的公共读取与复制不可用。若该发愿仍被公开发愿集引用，相关发愿集暂停公开，避免从组合详情继续泄露内容；已有独立副本与已开始的个人发愿不追溯删除。
- 当前默认通过只是接口占位，不代表已经实现真实 AI 内容安全审核。

### 账号与访问

- 继续现有固定账号登录，不增加注册、邮箱验证、密码找回或多用户管理界面。
- 发愿、发愿集、进度、收藏、点赞和计数明确关联当前所有者；不能因为当前只有一个用户就把所有数据当作全局共享。既有个人数据继续归属现有 owner。
- 作者才能修改原内容；复制后修改的是自己的副本。公共读取只返回通过审核的公开版本，不附带作者的草稿、个人进度或其他私有数据。
- 广场和审核通过的分享详情支持只读公开访问。写操作、保存进度、复制、收藏和点赞继续要求登录；未开放注册时，其他浏览者不会因此自动获得个人账号。
- 未来多用户测试可用不同所有者的测试数据验证隔离，无需为了测试增加生产注册接口。

### API 契约

- 提供发愿与发愿集的创建、读取、更新、删除，条目编排，单项和整集复制，送审、取消公开，公共列表与详情，收藏及点赞操作。
- 提供开始、继续、暂停、重新开始发愿及提交敲击的操作；返回当前轮次、条目、目标、已完成次数和完成状态，供页面统一使用。
- 私有读取、作者写入和公开读取使用明确的授权规则。请求验证聚焦外部输入、所有权、正整数次数和实际业务状态；不增加与需求无关的防御框架。
- 公共列表采用分页并有稳定顺序；搜索与排序只能作用于已审核公开内容。收藏引用与复制副本必须在返回结果中可区分。

## Testing Decisions

- 已由用户确认：以 API 请求配合隔离的本地 SQLite 数据库作为主要测试边界，执行实际迁移和业务 SQL；浏览器只补充关键页面与完整操作流程。
- 好的测试从输入、响应、后续读取与可见状态验证行为，不断言私有函数、SQL 字符串或内部调用次数。除审核服务等外部依赖外，不用整套数据库 mock 代替真实存储行为。
- 沿用现有构造请求并直接调用路由处理器的测试方式，复用内存 SQLite 与迁移执行经验；每个用例隔离数据库，避免现有模块级缓存污染结果。
- 现有敲击、计数状态和重试测试主要是单元测试，不能误称为已有完整 API 集成覆盖。保留这些回归测试，新增跨表行为测试。
- 内容与编排：验证创建、编辑、排序、移除、目标次数输入，以及同一内容在不同位置依次独立完成。
- 复制：验证单项及整集复制保留顺序与来源、内容独立可改、进度和互动不继承，以及原作撤回后已有副本不受影响。
- 进度与计数：验证临界一次敲击只完成当前项、自动推进、整集完成、主动重开、暂停恢复、跨日、时区及迟到事件。已开始的轮次不受作者后续改动影响。
- 可靠性：验证同事件重试、并发敲击、乱序响应、切换后的迟到请求和数据库写入失败。失败时不能出现事件已去重而计数或进度未提交的半完成状态。
- 隐私与归属：用两个测试身份验证私有数据隔离、原作者写权限和独立副本归属；匿名读取只能看到已审核公开版本，写入须登录。
- 审核：用可控制的适配器覆盖通过、拒绝、服务错误、旧审核结果和修改再送审；验证私有条目、未审核稿及被撤回内容不会从集合或分享入口泄露。
- 广场与互动：验证搜索、分页、稳定排行、收藏与复制的区别，以及点赞和取消操作的幂等性。
- 浏览器流程一：创建发愿、组合排序、开始敲击、过关、退出再继续直至完成；验证刷新后的已保存进度和桌面、手机布局。
- 浏览器流程二：发布内容、从广场查看与分享、复制并修改念诵内容、收藏和点赞；审核拒绝与服务错误状态使用测试适配器验证，界面不伪装成成功。
- 回归验证原有自由敲击、当日与累计统计、字幕、图片和音效。验证首页没有模式切换，提示不拦截敲击，长念诵内容不会遮挡计数或控制。
- 验证从已有数据库升级后旧数据完整；部署和本地演示执行相同迁移。最终运行现有测试、类型检查及相关构建检查，并启动本地演示供用户操作。

## Out of Scope

- 注册、密码找回、邮箱服务及面向公众的完整多用户账号运营。
- 真实 AI 审核服务接入、审核运营后台和复杂审核任务系统；本次仅实现可替换接口及发布约束。
- 现实行为打卡、连续天数要求、行为真实性验证、认知或修心效果评分。
- 评论、私信、关注动态、用户发愿成绩竞争及其他社交平台功能。
- 预设固定关卡、分支路线、地图探索或额外游戏世界系统。
- 新建发愿素材市场、图片上传体系、富文本脚本或音视频念诵内容；保留已有图片与音效能力即可。
- 全离线工作、多设备离线合并，以及关闭页面后恢复尚未发送的点击。
